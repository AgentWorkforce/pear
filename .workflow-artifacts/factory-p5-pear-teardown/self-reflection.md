# Factory P5 Pear Teardown Self-Reflection

## Changed Files

- `package.json`, `package-lock.json`: added `@agent-relay/factory@^0.1.1`; removed `npm run factory*` scripts that pointed at the vendored SDK.
- `factory.config.json`: added `factory` to `repos.names` so the schema derives `repos.byLabel.factory` as `AgentWorkforce/factory`.
- `packages/factory-sdk/**`: removed the vendored factory package now published as `@agent-relay/factory`.
- `src/main/factory-manager.ts`: deleted the local factory daemon manager.
- `bin/pear.mjs`: removed the `pear factory ...` CLI passthrough; the launcher now always launches Pear.
- `src/shared/types/ipc.ts`: removed factory `start`/`stop`; replaced daemon status fields with cloud status and NodeConfig-only config typing.
- `src/main/ipc-handlers.ts`: removed factory manager wiring and shutdown calls; added read-only cloud status probing and local NodeConfig read/write handlers.
- `src/main/index.ts`: removed factory manager shutdown from app shutdown.
- `src/preload/index.ts`: removed factory `start`/`stop` bridge methods.
- `src/renderer/src/components/factory/FactoryPage.tsx`: replaced the daemon control panel with a read-only cloud status view and NodeConfig editor.
- `src/renderer/src/components/common/AppTopBar.tsx`, `src/renderer/src/components/common/CommandMenu.tsx`, `src/renderer/src/components/settings/AccountSettings.tsx`, `src/renderer/src/lib/ipc-mock.ts`: updated text and mock IPC for read-only cloud status.
- `tsconfig.node.json`: removed stale include of the deleted `packages/factory-sdk/src/**/*`.
- `electron-builder.mcp-resources.yml`: regenerated by the build after npm dependency changes; verified with the drift check.

## Spec Coverage

- Deleted the in-Pear daemon model: no `FactoryManager`, no `factoryManager` singleton, no factory process spawn, no heartbeat/registry/reaper wiring, no `/tmp/factory-run` references.
- Removed `pear factory ...` passthrough and package scripts that invoked `packages/factory-sdk/bin`.
- Factory IPC no longer exposes `start` or `stop`; `status` probes cloud state through existing Pear cloud auth/workspace helpers and treats missing cloud factory endpoints as an empty read-only state.
- `readConfig`/`saveConfig` now return and write NodeConfig fields only: `workspaceId`, `capabilities`, `cloneRoot`, `clonePaths`, and `dryRun`.
- `FactoryPage` is read-only for cloud state and only edits NodeConfig locally.
- Pear now consumes `@agent-relay/factory` from npm for shared factory typing.

## Repo-Rule Alignment

- Followed the duplicate-event guidance by keeping factory status fetches side-effect-free and coalescing concurrent status calls with one in-flight promise.
- Did not change broker PTY/reconciler code.
- Kept local daemon teardown separate from broker lifecycle and did not add integration notifications or launch metadata.
- Preserved existing dirty worktree changes under `.trajectories/` and `.agentworkforce/trajectories/`; they were present before this implementation.

## Remaining Risks

- The cloud factory status endpoint is speculative until Phase 2 lands. Pear tries `/api/v1/workspaces/:workspaceId/factory/status`, `/api/v1/factory/status`, and `/api/factory/status`; 404/405/501 produce an empty read-only state instead of an error.
- `@agent-relay/factory@0.1.1` does not export `NodeConfig` from its root entrypoint, so Pear derives its NodeConfig IPC type from the exported `FactoryConfig` type plus local structural validation.
